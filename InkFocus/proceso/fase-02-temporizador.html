    Texto completo, tal como aparece en el Word

    Quiero que me ayudes a diseñar y desarrollar una aplicación web Pomodoro llamada InkFocus, para la asignatura Desarrollo de Interfaces de 2.º de DAM.

    Busco una aplicación completa, visualmente cuidada, funcional y con personalidad, inspirada en la estética de Splatoon. Necesito poder entender su código, probarla y explicar sus decisiones de interfaz.

    Trabaja conmigo por versiones funcionales. Este mensaje describe el proyecto completo para que mantengas una dirección coherente.

    1. Contexto académico y entrega

    El enunciado pide realizar una aplicación tipo Pomodoro y entregar un PDF con tres enlaces:

    • Aplicación web.
    • Repositorio de GitHub de esta tarea.
    • Página web con el proceso de resolución: prompts e IAs utilizadas en orden, distintas versiones y capturas.

    Por ahora céntrate en la aplicación. No construyas todavía la página del proceso ni el PDF de entrega. Yo documentaré el desarrollo en un Word o PDF y, al terminar, te lo proporcionaré para convertirlo en una página web coherente con el diseño de InkFocus.

    No inventes prompts, capturas, pruebas ni versiones. Al terminar cada versión, proporciona un resumen breve de sus cambios y una lista de comprobaciones que pueda realizar y capturar.

    2. Concepto principal

    InkFocus es una estación de concentración inspirada en Splatoon, con dos representaciones diferentes:

    • Tanque de tinta: representa el tiempo restante de la sesión.
    • Territorio del día: representa las tareas completadas de la fecha seleccionada.

    El calendario conecta las fechas con sus tareas, territorio e historial.

    La interfaz estará en español.

    3. Dirección visual

    Quiero una estética urbana, divertida y reconocible como inspirada en Splatoon:

    • Fondo carbón con textura sutil.
    • Combinación inicial de violeta y verde lima.
    • Manchas de tinta, pegatinas, formas orgánicas y algunos paneles ligeramente inclinados.
    • Títulos gruesos y expresivos, combinados con texto de lectura sencillo.
    • Botones grandes y estados visuales claros.
    • Ilustraciones originales mediante SVG y CSS para tanque, tinta y territorio.
    • Animaciones fluidas, moderadas y relacionadas con acciones reales.

    Evita una apariencia de plantilla genérica. Quiero que la temática esté integrada en los componentes y en su comportamiento.

    Mantén legibles los números, textos y formularios. Usa los elementos decorativos alrededor del contenido sin dificultar la interacción.

    No dependas de imágenes, música ni archivos oficiales de Nintendo para que la aplicación funcione. No uses iconos o emojis como sustitutos del diseño de los elementos principales.

    4. Temporizador y tanque

    Implementa:

    • Concentración, descanso corto y descanso largo.
    • Valores iniciales de 25, 5 y 15 minutos.
    • Descanso largo después de cuatro sesiones de concentración completadas.
    • Iniciar, pausar, continuar, reiniciar y saltar fase.
    • Duraciones y número de sesiones configurables.
    • Presets 25/5 y 50/10.
    • Inicio automático opcional, configurable para descansos y concentración.
    • Indicador de sesión dentro del ciclo.
    • Hora estimada de finalización de la fase.
    • Tiempo restante y fase en el título de la pestaña.

    El tanque debe ser el protagonista:

    • Se vacía proporcionalmente durante la concentración.
    • En el descanso se recarga de vacío a lleno.
    • Al pausar se detienen su progreso y animaciones de actividad.
    • El tiempo restante siempre aparece en números grandes y legibles.
    • Al terminar una fase aparece una transición breve de tinta.
    • El estado también se entiende mediante texto, sin depender solo del color.

    El temporizador debe calcular el tiempo mediante una referencia temporal para evitar acumular errores al cambiar de pestaña. Define el comportamiento al recargar o regresar tras mucho tiempo, sin inventar sesiones de concentración completadas automáticamente.

    Las sesiones saltadas o canceladas no deben contarse como completadas. Impide que un mismo final de sesión se registre dos veces.

    Si se cambian duraciones durante una sesión activa, explica cuándo se aplicarán y evita reinicios inesperados.

    5. Tareas y territorio diario

    Permite:

    • Crear, editar, completar, reabrir y eliminar tareas.
    • Deshacer una eliminación mediante un aviso temporal.
    • Asignar una fecha a cada tarea.
    • Añadir título, notas opcionales, categoría o asignatura y prioridad.
    • Estimar cuántos pomodoros requiere.
    • Ver pomodoros estimados y completados.
    • Seleccionar una tarea como activa y mostrarla junto al temporizador.
    • Buscar y filtrar por estado o categoría.

    Completar un pomodoro aumenta el contador de la tarea activa, pero no la marca automáticamente como terminada. El usuario decide cuándo está completada.

    El territorio representa las tareas del día:

    • Cada tarea ocupa una región identificable de un pequeño mapa original.
    • Completarla pinta su región con una animación breve.
    • Reabrirla devuelve su región al estado pendiente.
    • Muestra también el progreso en texto, por ejemplo «3 de 5 tareas».
    • Al seleccionar una región se identifica su tarea.
    • Las regiones deben poder usarse con teclado o disponer de un control equivalente accesible.
    • El mapa debe mantener una distribución estable mientras no cambie la lista de tareas.
    • Si no hay tareas, muestra un estado vacío útil.

    Distingue claramente este progreso del objetivo diario de concentración.

    6. Calendario integrado

    Incluye un calendario mensual con:

    • Navegación entre meses y botón «Hoy».
    • Fecha seleccionada claramente indicada.
    • Distinción visual entre hoy y el día seleccionado.
    • Indicadores de tareas pendientes, tareas completadas y actividad de estudio.
    • Leyenda breve para entender esos indicadores.
    • Selección de una fecha para consultar sus tareas y territorio.
    • Creación de tareas para la fecha seleccionada.
    • Resumen del día: tareas completadas, sesiones y minutos de concentración.
    • Uso cómodo en móvil y mediante teclado.

    Seleccionar un día pasado o futuro cambia la planificación que se consulta, sin alterar el temporizador activo.

    Registra la actividad real en la fecha en la que ocurre, aunque la tarea estuviera planificada para otro día. Usa fechas locales de forma consistente y define cómo se registra una sesión que cruza medianoche.

    7. Objetivos, estadísticas e historial

    Añade:

    • Objetivo diario configurable de sesiones de concentración.
    • Progreso hacia ese objetivo separado del territorio de tareas.
    • Minutos de concentración y sesiones completadas.
    • Gráfico sencillo de actividad de los últimos siete días, con alternativa textual.
    • Historial con fecha, duración y tarea asociada cuando exista.
    • Filtro del historial por fecha o tarea.
    • Algunas insignias por hitos acumulativos: primera sesión, diez sesiones o cinco horas de concentración.

    Los descansos no suman tiempo de estudio. Pausas y cancelaciones deben tener un tratamiento coherente y explicado.

    Las recompensas serán discretas y opcionales, sin penalizaciones ni mensajes de culpa.

    8. Personalización y utilidades

    Incluye:

    • Varias parejas de colores de tinta.
    • Tema claro y oscuro.
    • Modo concentración que oculte los paneles secundarios.
    • Sonido breve al finalizar una fase, control de volumen y silencio.
    • Notificaciones del navegador opcionales, solicitadas cuando el usuario las active.
    • Alternativa visual si no hay permiso para notificar.
    • Atajos de teclado documentados, desactivados al escribir en campos.
    • Ayuda breve sobre la técnica Pomodoro.
    • Exportación e importación de datos en JSON, validando el archivo antes de modificar datos.
    • Restablecimiento de datos con confirmación.
    • Modo demostración con fases de pocos segundos, claramente indicado y sin contaminar las estadísticas reales.

    El sonido debe respetar las restricciones del navegador y activarse a partir de una interacción del usuario.

    9. Guardado y robustez

    Guarda localmente tareas, preferencias, historial y objetivos para conservarlos al recargar.

    Valida duraciones, títulos y archivos importados. Maneja datos guardados ausentes o incorrectos sin dejar la aplicación inutilizable.

    Evita contenido de ejemplo que parezca actividad real. Si incluyes datos de demostración, identifícalos y permite retirarlos.

    No implementes cuentas, backend o sincronización en la nube: el alcance inicial es una aplicación de uso local que pueda publicarse como web estática.

    10. Organización de la interfaz

    En escritorio:

    • Cabecera con identidad, personalización y ajustes.
    • Temporizador y tanque como foco principal.
    • Tareas en un panel lateral.
    • Territorio y objetivo diario en otro panel.
    • Calendario, estadísticas e historial en vistas o pestañas bien organizadas.

    No muestres todas las funciones a la vez si dificulta usar el temporizador.

    En móvil, prioriza temporizador y controles, reorganizando el resto sin desplazamiento horizontal.

    Cuida estados vacíos, botones deshabilitados, mensajes de validación, avisos y confirmaciones.

    11. Accesibilidad

    Incluye:

    • HTML semántico.
    • Etiquetas en formularios y nombres accesibles en botones.
    • Navegación mediante teclado y foco visible.
    • Contraste suficiente.
    • Estados identificables sin depender del color.
    • Respeto por la preferencia de movimiento reducido.
    • Gestión del foco en ventanas de ajustes y confirmaciones.
    • Anuncios accesibles para cambios de fase, evitando anunciar cada segundo.

    12. Tecnología y código

    Si no existe ninguna restricción adicional, utiliza HTML, CSS y JavaScript modular, con archivos separados y una estructura comprensible para un estudiante de 2.º de DAM.

    Evita introducir un framework o dependencias sin una ventaja concreta. El resultado debe poder publicarse como sitio estático en GitHub Pages.

    Organiza el código por responsabilidades, con nombres claros y comentarios donde ayuden a entender decisiones importantes. Incluye instrucciones para ejecutarlo y un README.

    Si este entorno permite crear archivos, trabaja directamente en ellos. Si solo permite responder con texto, entrega el código completo de los archivos necesarios para cada versión y explica dónde colocarlos.

    13. Desarrollo por versiones

    Propón un plan breve y comienza directamente con la primera versión sin esperar confirmaciones rutinarias.

    La primera versión debe ser funcional y mostrar ya la identidad visual de InkFocus: temporizador, tanque, controles, fases y adaptación básica a móvil.

    Después iremos incorporando tareas y territorio, calendario, persistencia, estadísticas, personalización y detalles finales. Puedes ajustar el orden si hay dependencias que lo aconsejen.

    Cada versión debe mantener lo que ya funciona y añadir una parte coherente. No intentes generar todas las funciones de golpe.

    Al terminar cada versión:

    • Resume lo implementado y lo pendiente.
    • Explica las decisiones de interfaz más relevantes.
    • Indica cómo probar sus funciones y qué capturas conviene guardar.
    • Distingue las comprobaciones ejecutadas de las que debo realizar yo.
    • Sugiere un mensaje de commit descriptivo.

    Comienza ahora con el plan breve y la implementación de la primera versión.
